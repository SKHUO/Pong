# Pong 产品设计文档

## 1. 产品概述

Pong 是一款基于 Godot 的 2D 双人对抗小游戏。双方先各自选择角色，再控制分界线两侧的挡板反弹小球进行对战。游戏采用 1800×720 的 5:2 固定画面；白色角色与小球尺寸不变，红色角色拥有更长挡板。

对战参考真实乒乓球运动，引入较温和的空气阻力、旋转、摩擦和 Magnus 侧向力，使发球与反弹轨迹会随玩家动作变化。

## 2. 游戏流程

1. 启动后先进入角色选择页。
2. 两名玩家各自选择角色。
3. 按下空格，双方以当前所选角色进入对战。
4. 开局小球附着在 Player 1 身上，等待其发球。
5. 小球从左右侧出界，或最后触球方在自己半场内碰到上下边界时，该方输掉本轮，对方获胜。
6. 每轮赢家加 1 分；下一轮双方回到初始位置，由上一轮赢家发球，角色和比分保持不变。

## 3. 角色选择页

| 项目 | 设计要求 |
| --- | --- |
| 布局 | 画面被中央分界线分为左右两半，左侧属于 Player 1，右侧属于 Player 2 |
| 角色选项 | 用不同颜色的方块表示；两侧的可选角色完全相同 |
| 排列 | 方块按网格排列，从左到右、从上到下依次摆放 |
| 默认选中 | 双方默认选中第一个角色 |
| Player 1 选中标记 | 低饱和度蓝色（#6CA6D9）方框，框住当前所选方块 |
| Player 2 选中标记 | 低饱和度绿色（#67C795）方框，框住当前所选方块 |
| 开始提示 | 底部提示“空格 开始游戏” |

## 4. 角色列表

| 角色 | 说明 |
| --- | --- |
| 白色角色 | 初始角色；未持球时按本侧行动键，获得 100% 移速加成，持续 0.5 秒，冷却 1.5 秒，移动时留下渐隐幻影 |
| 红色角色 | 红色外观，挡板长度为白色角色的两倍，无技能 |

## 5. 对战画面

| 项目 | 设计要求 |
| --- | --- |
| 画面比例 | 5:2 |
| 背景 | 纯黑色，铺满整个游戏画面 |
| 分界线 | 白色纵向线，位于画面正中央，将游戏区域分为左右两半 |
| 比分 | 双方数字均为白色，位于屏幕顶部并分居中央分界线左右；初始均为 0，每赢一轮加 1 分 |
| Player 1 挡板 | 纵向长方体，初始位于左半场中心，颜色和长度由所选角色决定 |
| Player 2 挡板 | 纵向长方体，初始位于右半场中心，颜色和长度由所选角色决定 |
| 小球 | 小方块；最后触球方为 Player 1 时为低饱和度蓝色（#6CA6D9），为 Player 2 时为低饱和度绿色（#67C795） |

## 6. 操作方式

| 场景 | 玩家 | 操作 | 按键 |
| --- | --- | --- | --- |
| 角色选择 | Player 1 | 移动选择 | `W` / `S` / `A` / `D` |
| 角色选择 | Player 2 | 移动选择 | 方向键 `↑` / `↓` / `←` / `→` |
| 角色选择 | 双方 | 开始游戏 | 空格 |
| 对战 | Player 1 | 上、下、左、右移动 | `W` / `S` / `A` / `D` |
| 对战 | Player 2 | 上、下、左、右移动 | 方向键 `↑` / `↓` / `←` / `→` |
| 对战 | Player 1 | 持球时发球；使用白色角色且未持球时加速 | `J` |
| 对战 | Player 2 | 持球时发球；使用白色角色且未持球时加速 | 小键盘 `1` |

## 7. 核心玩法规则

1. 开局小球不自动发射，而是紧贴 Player 1 朝向 Player 2 的一侧，并随 Player 1 移动。
2. 发球方向仅由朝对手方向和发球者当前移动方向决定；静止时正对对手，移动时稳定向移动方向偏转，不使用随机角。
3. 发球者移动越快，出球速度略高，并可能获得与移动方向相关的初始旋转。
4. Player 1 持球时按 `J` 发球；Player 2 持球时按小键盘 `1` 发球。
5. 玩家可以上下左右移动，但会被屏幕边界和中央分界线阻挡，不能越过分界线。
6. 小球具有速度和旋转。较小的空气阻力会持续降低速度，旋转产生侧向 Magnus 力并让轨迹弯曲，旋转也会逐渐衰减。
7. 小球碰到挡板时按法向恢复和切向摩擦处理：恢复系数决定反弹速度，摩擦根据球与挡板的相对滑动改变出射方向和旋转。
8. 挡板的移动方向与速度会影响反弹，上下挥动可制造明显的反弹角度变化和旋转。
9. 最后触球方在自己半场内碰到上/下边界时立即输；在对方半场碰到上/下边界时正常反弹。
10. 小球颜色表示最后触球方：Player 1 为低饱和度蓝色（#6CA6D9），Player 2 为低饱和度绿色（#67C795）。
11. 小球从左侧出界，Player 1 输、Player 2 赢；从右侧出界则相反。
12. 每轮赢家加 1 分，比分在当前对战中持续累计。
13. 每轮结束后双方回到各自半场的中心位置，下一轮由赢家持球并等待发球。
14. 白色角色未持球时按本侧行动键，可获得 100% 移速加成；持续 0.5 秒，冷却 1.5 秒。
15. 持球时本侧行动键优先用于发球；红色角色未持球时按键不产生效果。
16. 红色角色挡板的长度为白色角色的两倍，宽度保持不变。

## 8. 验收标准

- 初始窗口为 1800×720，画面比例为 5:2。
- 启动游戏后首先看到角色选择页，页面由左右两部分和中央分界线组成。
- 两侧可选角色完全相同，均以彩色方块表示，且排列规则一致。
- Player 1 的选中方块被低饱和度蓝色（#6CA6D9）方框标记，Player 2 的选中方块被低饱和度绿色（#67C795）方框标记。
- 两名玩家可分别用各自按键移动选择，选中标记随之移动。
- 按下空格后，双方以当前所选角色进入对战，挡板显示对应角色颜色。
- 对战中包含黑色背景、中央分界线、顶部双方比分、两个玩家和一个小球等核心视觉对象。
- 玩家初始位置分别位于左半场和右半场的几何中心。
- 开局小球附着在 Player 1 朝向对手的一侧并跟随其移动，不自动发球。
- 发球时球始终朝向对手一侧；静止时笔直朝对手，移动时稳定向发球者瞬时移动方向偏转，不出现随机方向。
- 发球后球受较小的空气阻力和旋转影响；不同旋转会产生方向相反的弯曲轨迹，旋转衰减后轨迹逐渐变直。
- 球与挡板碰撞时能根据接触位置和挡板速度产生不同反弹角度，切向摩擦会改变球的旋转。
- 最后触球方在自己半场内碰到上、下边界时判负；在对方半场碰到时会正常反弹。
- 最后触球方为 Player 1 时小球显示低饱和度蓝色（#6CA6D9），为 Player 2 时显示低饱和度绿色（#67C795）。
- 高球速下球不会直接穿透挡板。
- 小球从任一侧出界后，判定该侧玩家输、对方赢；赢家比分加 1，下一轮由赢家持球。
- 屏幕顶部由中央分界线分隔双方比分，数字为白色且初始为 0；每轮赢家加 1 分，比分持续累计。
- 每轮角色颜色保持不变。
- 白色角色未持球时按本侧行动键，移动速度提升 100%，持续 0.5 秒，冷却 1.5 秒。
- 加速期间移动会留下与挡板同形状、同颜色的半透明幻影，幻影随后渐隐消失。
- 加速期间再次按键或冷却未结束时不会重复触发。
- 持球时本侧行动键仍然发球；红色角色未持球时按键不会加速。
- 红色角色挡板长度为白色角色的两倍，宽度与白色角色相同。

## 9. 项目维护

- 场景与脚本按角色选择、对战、共享组件、角色数据分类管理。
- 本次新增基于速度与旋转的对战物理、受发球者速度影响的发球方式、白色角色的短时加速和幻影拖尾、红色角色的加长挡板，按最后触球方归属的上下边界判负规则，随最后触球方切换颜色的小球，以及由中央分界线分隔的白色累计比分。角色选择标识与小球归属色统一使用低饱和度的蓝色和绿色。
